PostgreSQL 개발자를 위한 Cypher 그래프 쿼리 가이드

테이블과 조인(JOIN) 사고방식에서 노드와 관계(Edge) 중심의 내비게이션 모델로 전환하기

1. RDBMS (PostgreSQL) vs Cypher 개념 대조

PostgreSQL에 익숙한 개발자는 그래프 데이터베이스의 용어를 기존 DB 개념에 대입하면 빠르게 이해할 수 있습니다.

개념 PostgreSQL (RDBMS) Cypher (Graph DB / Neo4j) 설명
실체 (Entity) 행 (Row) / 레코드 노드 (Node) 개별 데이터 객체 (예: 개별 메서드, 예외, 스레드)
분류 (Type) 테이블명 (Table Name) 라벨 (Label) 노드의 종류를 구분 (예: :Method, :Exception)
연결 (Link) 외래키 (FK) + JOIN 테이블 관계 (Relationship / Edge) 노드와 노드를 물리적으로 직접 잇는 포인터 연결
속성 (Data) 컬럼 (Column) 속성 (Property) 노드나 관계 내부에 Key-Value 형태로 저장되는 데이터
조회 (Query) SELECT ... FROM ... JOIN MATCH ... RETURN 연결된 패스(Path) 모양을 시각적으로 묘사하여 검색
💡 핵심 차이: JOIN 연산의 본질적 차이
RDBMS는 외래키 값을 대조하는 비교 연산(Index Lookup / Hash Join)을 수행하지만, Graph DB는 메모리상에서 연결된 포인터를 바로 따라가는 Pointer Hopping (Index-free Adjacency) 방식을 사용합니다. 따라서 관계가 10단계 이상 깊어져도 검색 성능이 저하되지 않습니다.

2. Cypher 문법 요소 및 핵심 기호 정의

Cypher는 아스키 아트(ASCII Art)처럼 데이터의 연결 상태를 시각적으로 그리듯이 작성합니다.

( ) - 소괄호
노드 (Node)

그래프상의 '점'을 뜻합니다. 테이블의 Row에 대응합니다.

예: (m:Method)

[ ] - 대괄호
관계 (Relationship)

노드를 잇는 '선'을 뜻합니다. FK / JOIN 역할을 대신합니다.

예: -[r:CALLS]->

- & -> - 방향키
관계의 방향성

-는 양방향(무방향), ->는 단방향 흐름을 뜻합니다.

예: (Caller)-[:CALLS]->(Callee)

p = ... - 패스 변수
경로 (Path)

노드-관계-노드로 이어지는 전체 구성을 묶은 객체입니다.

예: MATCH p = (a)-[r]->(b)

변수 (Alias) 할당의 이해

SQL에서 FROM users AS u처럼 테이블이나 컬럼에 별칭을 붙이듯, Cypher에서는 노드나 관계 앞에 별칭을 작성합니다.

MATCH (caller:Method)-[r:CALLS]->(callee:Method)
RETURN caller.fullName, callee.fullName

3. [실습] 장애 분석(RCA) 데이터 모델 정의 및 데이터 생성 (CREATE)

조회 쿼리를 이해하기 전, 그래프 DB에 데이터가 어떤 구조로 적재되는지 CREATE 문을 통해 먼저 살펴봅니다.

📋 분석 대상 노드 (m:Method)가 보유한 속성 정의

속성명 (Property) 데이터 타입 설명 (RDBMS 컬럼 대응) 예시 값
m.name String 메서드 단독 이름 "authenticate"
m.fullName String 패키지명을 포함한 전체 메서드 명 "com.auth.Service.authenticate"
m.isFramework Boolean 프레임워크 내부 코드 여부 false (사용자 코드) / true
m.executionTime Integer 수행 시간 (ms) 650

🛠️ 샘플 데이터 적재 (CREATE 쿼리)

스레드가 예외를 일으키고, 예외가 특정 메서드에서 발생했으며, 메서드 간에 호출(CALLS)이 이루어지는 구조를 생성합니다.

-- 1. 스레드, 예외, 메서드 노드를 생성하고 관계(-[:RAISED]->, -[:OCCURRED_IN]->)로 연결합니다.
CREATE (t:Thread { name: "http-nio-8080-exec-1" })
       -[:RAISED]->
       (ex:Exception { type: "NullPointerException", message: "User object is null" })
       -[:OCCURRED_IN]->
       (m1:Method { name: "authenticate", fullName: "com.auth.AuthService.authenticate", isFramework: false, executionTime: 650 });

-- 2. 메서드 간 호출 관계(CALLS)를 추가로 생성합니다.
CREATE (m2:Method { name: "doLogin", fullName: "com.web.LoginController.doLogin", isFramework: false, executionTime: 800 })
       -[r:CALLS { callCount: 12 }]->
       (m1);

4. 속성(Properties)을 활용한 조건 필터링 쿼리 (MATCH)

앞서 적재된 데이터를 대상으로 조건에 맞는 노드를 조회하는 MATCH 쿼리 예시입니다.

① 인라인 필터: 노드 생성 시점의 속성 지정

-- PostgreSQL: SELECT fullName FROM methods WHERE name = 'authenticate';
MATCH (m:Method { name: 'authenticate' })
RETURN m.fullName;

② WHERE 절을 이용한 속성 조건 필터링

-- PostgreSQL: SELECT fullName, execution_time FROM methods 
--            WHERE is_framework = false AND execution_time > 500 ORDER BY execution_time DESC;
MATCH (m:Method)
WHERE m.isFramework = false AND m.executionTime > 500
RETURN m.fullName, m.executionTime
ORDER BY m.executionTime DESC;

5. 실무 애플리케이션 장애 분석(RCA) 쿼리 해설

패턴 1. 전체 연결 그래프 시각화 (Path 바인딩)

MATCH p = (t:Thread)-[:RAISED]->(ex:Exception)-[:OCCURRED_IN]->(m:Method)
RETURN p
LIMIT 30;

패턴 2. 통계 집계 및 필터링 (GROUP BY 자동 처리)

MATCH (ex:Exception)-[:OCCURRED_IN]->(m:Method)
WHERE m.isFramework = false
RETURN 
    m.fullName AS CustomMethod, 
    ex.type AS ExceptionType, 
    count(ex) AS ErrorCount
ORDER BY ErrorCount DESC
LIMIT 10;
💡 자동 GROUP BY 특징
Cypher는 count() 같은 집계 함수를 사용할 때 SQL처럼 GROUP BY 절을 명시할 필요 없이, RETURN에 포함된 비집계 컬럼을 기준으로 자동 GROUP BY를 수행합니다.

6. 가이드 요약 (Cheat Sheet)

  1. 데이터 생성(`CREATE`): 조회 전, 노드와 관계를 시각적인 모양 그대로 엮어서 적재합니다.
  2. 괄호 구분: 노드는 동그란 소괄호 (), 관계는 사각형 대괄호 []로 표기합니다.
  3. 화살표 방향: (a)-[r]->(b)는 a에서 b로 향하는 방향이 존재하는 관계입니다.
  4. 속성 접근: PostgreSQL의 컬럼처럼 m.name, ex.type 형태로 속성값을 읽거나 조건에 활용합니다.
  5. 시각화: p = (패턴) 형태로 저장 후 RETURN p 하면 그래프 화면 전체가 출력됩니다.
